### 国际化

`@nestjs/i18n` 将 Nest 应用程序返回的内容（响应、错误、验证消息、GraphQL 字段）翻译成每个请求的语言。

一个销售猫粮和用品的在线商店面向美国、波兰和德国的客户，其订单 API 应以各自的语言回答他们。在本教程中，您将翻译订单确认（包含正确的波兰复数形式）、错误消息、验证消息（来自 `class-validator` 或来自 Zod）和 GraphQL 字段。您还将为每个区域格式化价格和日期。

该包在每次请求中解析一次区域，并将其保存在 `AsyncLocalStorage` 存储中。服务、异常、管道和 GraphQL 字段解析器在没有访问请求对象的情况下进行翻译，并且每个提供者都保持单例。它在 Express 和 Fastify 上，以及在微服务和 WebSocket 网关上都以相同的方式工作。

#### 安装

本教程扩展了存储的订单 API，该 API 为英语、波兰语和德语的客户提供服务。订单是保存在内存中的纯对象。示例播种了订单 #1001：两袋鲑鱼幼粮和三包凝结猫砂，总计 $97.95。该订单于 2026 年 9 月 14 日下达，并且已发货。

```bash

```

#### 添加目录和注册模块

翻译存储在 JSON 文件中，每个区域对应一个目录。每个文件都成为一个以文件名命名的命名空间，因此 `orders.json` 中的 `notFound` 消息具有键 `orders.notFound`。

```text
src
├── i18n
│   ├── de
│   │   ├── orders.json
│   │   └── validation.json
│   ├── en
│   │   ├── orders.json
│   │   └── validation.json
│   ├── pl
│   │   ├── orders.json
│   │   └── validation.json
│   └── translations.ts
├── orders
└── app.module.ts

```

这是订单的英语目录。花括号中的词是占位符，从翻译时传入的参数中填充。`items` 是一个复数消息，[Translate order confirmations](/application/i18n#translate-order-confirmations) 进行了说明。

```json
{
  "items": {
    "one": "{count} item",
    "other": "{count} items"
  },
  "confirmed": "Thank you! Order #{id} is confirmed: {items}.",
  "notFound": "Order #{id} was not found.",
  "invalidId": "The order number must be a whole number.",
  "unknownProduct": "Product {id} is not in our catalog.",
  "tooManyItems": {

```

现在在根模块中注册 `I18nModule`：

```typescript title="app.module.ts"
import { Module } from '@nestjs/common';
import {
  AcceptLanguageLocaleResolver,
  HeaderLocaleResolver,
  I18nModule,
  JsonI18nLoader,
  QueryLocaleResolver,
} from '@nestjs/i18n';
import { join } from 'node:path';
import { OrdersModule } from './orders/orders.module.js';

@Module({
  imports: [
    I18nModule.forRoot({
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
      }),
      resolvers: [
        new QueryLocaleResolver('lang'),
        new HeaderLocaleResolver('x-lang'),
        new AcceptLanguageLocaleResolver(),
      ],
    }),
    OrdersModule,
  ],
})
export class AppModule {}

```

该模块是全局的，它在每个路由上挂载一个中间件，该中间件在守卫、拦截器、管道和处理器运行之前解析区域。解析工作方式如下：

- **解析器按顺序运行。** 每个返回一个或多个候选者，第一个匹配支持的区域的候选者获胜。在这里，`?lang=pl` 胜过 `x-lang` 头部，后者胜过 `Accept-Language`。
- **`Accept-Language` 被正确解析。** 语言按其 `q` 值排序，不支持的语言被跳过，因此 `fr-CH, fr;q=0.9, de;q=0.8` 解析为 `de`。
- **区域匹配其基础语言。** `pl-PL` 解析为 `pl`。无需配置。
- **`fallbacks` 将一个区域保留为其自身的区域。** `de-AT` 解析为 `de-AT`，其消息来自 `de`。当 [formatting prices and dates](/application/i18n#format-prices-and-dates) 时，区域很重要：奥地利客户获得奥地利数字格式。未列出的区域，例如 `de-CH`，解析为纯 `de`。
- **没有匹配项，或者根本没有请求**（定时任务、队列消费者）：使用 `defaultLocale`。

`CookieLocaleResolver` 读取 Cookie，默认情况下是 `lang`，适用于记住访客选择的语言的网站。[Use the customer's saved language](/application/i18n#use-the-customers-saved-language) 添加了您自己的解析器。

每个响应都会说明其使用的区域。中间件将 `Content-Language` 设置为解析的区域，并将解析器读取的头部添加到 `Vary`（此处为 `Vary: x-lang, Accept-Language`），以便缓存为每种语言保留一份副本。设置 `responseHeaders: false` 以关闭此功能。

`supportedLocales` 是可选的，默认为加载器找到的目录。固定它意味着一个意外的目录永远不会成为一个区域。

最后，为您的键指定类型。英语目录是事实来源，仅类型导入在编译时读取其形状而无需加载文件。`declare module` 块将该形状注册到包中：

```typescript title="i18n/translations.ts"
import type orders from './en/orders.json';
import type validation from './en/validation.json';

export interface Translations {
  orders: typeof orders;
  validation: typeof validation;
}

declare module '@nestjs/i18n' {
  interface I18nTypes {
    translations: Translations;
  }
}

```

从现在起，`I18nService` 和您将用于本地化异常和验证消息的辅助函数 `t()`、`i18nValidationMessage()` 和 `i18nIssueMessage()`，只接受存在于英语目录中的键。像 `orders.notFund` 这样的拼写错误会导致编译失败，同样 `orders.status` 也会失败，因为它是一个命名空间而不是一个消息。从具有不同形状的目录（例如库）翻译的提供者注入 `I18nService<OtherTranslations>`，它检查键是否与 `OtherTranslations` 匹配。

#### 翻译订单确认

当客户下订单时，API 会用包含项目数量的消息来确认订单。将 `I18nService` 注入到 `OrdersService` 中并调用 `t()`：

```typescript title="orders/orders.service.ts"
@Injectable()
export class OrdersService {
  // ...
  constructor(private readonly i18nService: I18nService) {}

  create(userId: number, dto: CreateOrderDto) {
    const order: Order = {
      id: this.nextId++,
      userId,
      items: dto.items,
      total: this.priceOf(dto.items),
      status: 'pending',
      createdAt: new Date(),
    };
    this.orders.push(order);

    return {
      id: order.id,
      message: this.i18nService.t('orders.confirmed', {
        args: { id: order.id, items: this.describeItems(order) },
      }),
    };
  }

  describeItems(order: Order): string {
    const count = order.items.reduce((sum, item) => sum + item.quantity, 0);
    return this.i18nService.t('orders.items', { args: { count } });
  }
  // ...
}

```

您不向 `t()` 传递区域。它读取当前请求解析的区域，尽管 `OrdersService` 是一个单例，永远看不到请求。仅设置 `locale` 选项以覆盖它，例如当后台任务以客户个人资料中保存的语言向客户发送电子邮件时。该选项的匹配方式与请求区域的匹配方式相同：`pl-PL` 变为 `pl`，不支持的区域将成为默认区域，因此过时的个人资料值不会破坏任务。

英语和德语有两种复数形式。波兰语有四种，而数字采用哪一种取决于其最后几位数字。复数消息是一个按复数类别键控的对象：

```json
{
  "items": {
    "one": "{count} produkt",
    "few": "{count} produkty",
    "many": "{count} produktów",
    "other": "{count} produktu"
  },
  "confirmed": "Dziękujemy! Zamówienie #{id} zostało przyjęte: {items}.",
  "notFound": "Nie znaleziono zamówienia #{id}.",
  "invalidId": "Numer zamówienia musi być liczbą całkowitą.",
  "unknownProduct": "Produktu {id} nie ma w naszym katalogu.",
  "tooManyItems": {
    "one": "{path}: można zamówić najwyżej {count} sztukę jednego produktu",
    "few": "{path}: można zamówić najwyżej {count} sztuki jednego produktu",
    "many": "{path}: można zamówić najwyżej {count} sztuk jednego produktu",
    "other": "{path}: można zamówić najwyżej {count} sztuki jednego produktu"
  },
  "unsupportedCountry": "Wysyłamy tylko do Stanów Zjednoczonych, Polski i Niemiec.",
  "status": {
    "pending": "Oczekuje na płatność",
    "paid": "Opłacone",
    "shipped": "Wysłane"
  }
}

```

当参数包含数字 `count` 时，服务会为消息的区域选择具有 `Intl.PluralRules` 的形式。如果缺少类别，则使用 `other`。德语文件镜像英语文件，仅包含 `one` 和 `other` 形式。

| Items | English | Polish | German |
| --- | --- | --- | --- |
| 1 | 1 item | 1 produkt | 1 Produkt |
| 2 | 2 items | 2 produkty | 2 Produkte |
| 5 | 5 items | 5 produktów | 5 Produkte |
| 22 | 22 items | 22 produkty | 22 Produkte |

确认由两个消息组成：先翻译复数短语，然后将其插入到句子中。占位符不能嵌套，因此组合方式如下：

占位符的名称由字母、数字和下划线组成。未提供参数的占位符将按原样保留在文本中，花括号中的任何其他文本也是如此。要将花括号写在名称旁边，请将其加倍：<code>{{id}}</code> 打印 <code>{id}</code>。对于选择、序数和精确匹配，请使用 [use ICU message syntax](/application/i18n#use-icu-message-syntax)。

> info **提示** 只有 `count` 参数会选择复数形式，因此在您使用 `t()` 翻译的每个复数消息中，请将其命名为 `count`。得益于已注册的目录类型，没有它，`t()` 不会编译复数消息。验证消息会自动获得 `count`，如 [Localize validation messages](/application/i18n#localize-validation-messages) 所示。

#### 本地化异常

缺少订单应以客户的语言返回 404。在抛出时翻译消息：

```typescript title="orders/orders.service.ts"
findOne(id: number): Order {
  const order = this.orders.find((order) => order.id === id);
  if (!order) {
    throw new NotFoundException(this.i18nService.t('orders.notFound', { args: { id } }));
  }
  return order;
}

```

异常携带了最终文本，因此无需配置：Nest 的默认异常过滤器、您自己的过滤器和 GraphQL 错误格式化都会接收到翻译后的消息。使用 `GET /orders/999` 和 `x-lang: pl` 返回：

```json
{
  "message": "Nie znaleziono zamówienia #999.",
  "error": "Not Found",
  "statusCode": 404
}

```

没有 `I18nService` 的代码可以使用 `t()` 函数。它以相同的方式为当前请求进行翻译。像 `ParseIntPipe` 这样的内置管道会产生英文消息，因此请为解析订单 ID 的管道提供一个异常工厂：

```typescript title="orders/orders.controller.ts"
const orderIdPipe = new ParseIntPipe({
  exceptionFactory: () => new BadRequestException(t('orders.invalidId')),
});

@Controller('orders')
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}
  // ...

  @Get(':id')
  findOne(@Param('id', orderIdPipe) id: number) {
    return this.ordersService.getSummary(id);
  }
}

```

该管道在依赖注入外部创建一次，但仍以其自身的语言响应每个请求。您将在 [Format prices and dates](/application/i18n#format-prices-and-dates) 中编写 `getSummary()`。

如果您的 API 使用自己的 [exception filter](/overview/exception-filters#绑定过滤器) 来格式化错误，例如作为 RFC 9457 问题详情，则过滤器会像读取任何其他消息一样读取翻译后的消息：

```typescript title="common/problem-details.filter.ts"
import {
  Catch,
  NotFoundException,
  type ArgumentsHost,
  type ExceptionFilter,
} from '@nestjs/common';
import { HttpAdapterHost } from '@nestjs/core';

@Catch(NotFoundException)
export class ProblemDetailsFilter implements ExceptionFilter {
  constructor(private readonly httpAdapterHost: HttpAdapterHost) {}

  catch(exception: NotFoundException, host: ArgumentsHost) {
    const { httpAdapter } = this.httpAdapterHost;
    const response = host.switchToHttp().getResponse();
    httpAdapter.setHeader(response, 'Content-Type', 'application/problem+json');
    httpAdapter.reply(
      response,
      { type: 'about:blank', title: 'Not Found', status: 404, detail: exception.message },
      404,
    );
  }
}

```

注册了过滤器后，相同的请求返回：

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "Nie znaleziono zamówienia #999."
}

```

#### 本地化验证消息

此步骤假设您的应用程序使用 `class-validator` 验证请求主体；如果使用 Zod 或其他标准 ⟦Schema⟧ 库进行验证，请继续阅读 [With Zod](#with-zod)。`I18nValidationPipe` 是 Nest [`ValidationPipe`](/techniques/validation#using-the-built-in-validationpipe) 的即插即用替代品：它接受相同的选项，并且只翻译消息。将其绑定到 `ValidationPipe` 所在的位置，此处作为 `AppModule` 的 `APP_PIPE` 提供者：

```typescript title="app.module.ts"
providers: [
  {
    provide: APP_PIPE,
    useValue: new I18nValidationPipe({ whitelist: true, transform: true }),
  },
],

```

从新订单的 ⟦DTO⟧ 开始。它使用不带任何消息的 `class-validator` 装饰器：

```typescript title="orders/dto/create-order.dto.ts"
import { i18nValidationMessage } from '@nestjs/i18n';
import { Type } from 'class-transformer';
import { ArrayNotEmpty, IsInt, IsString, Max, Min, ValidateNested } from 'class-validator';

export class OrderItemDto {
  @IsString()
  productId: string;

  @IsInt()
  @Min(1)
  @Max(10, { message: i18nValidationMessage('orders.tooManyItems') })
  quantity: number;
}

export class CreateOrderDto {
  @ArrayNotEmpty()
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  items: OrderItemDto[];
}

```

没有 `message` 的约束将根据约束名称在 `validation` 命名空间中查找：`@IsInt()` 读取 `validation.isInt`，而 `@Min()` 读取 `validation.min`。`i18nValidationMessage()` 将单个约束指向您选择的键，此处是针对项目限制的特定于存储的消息。您作为纯字符串编写的消息保持不变。消息可以使用这些占位符：

- `property`：字段名称，例如 `quantity`。
- `path`：从 ⟦DTO⟧ 的点路径，例如 `items.1.quantity`。对于顶层字段，它与 `property` 相同。
- `value`：被拒绝的值，如果它是字符串、数字或布尔值。
- `constraint1`、`constraint2` 等：装饰器的参数。一个列表，例如 `@IsIn()` 接受的值，读取 `US, PL, DE`。
- `count`：第一个数字参数，因此复数消息与其保持一致。`@Max(10)` 为 10 选择形式。

项目限制是一个复数消息（参见 [Translate order confirmations](/application/i18n#translate-order-confirmations) 中的波兰语目录），因此 `@Max(10)` 在波兰语中读取 "10 sztuk"。这是本教程使用的约束的波兰语 `validation` 目录。`minLength` 也是一个复数消息，因此 `@MinLength(2)` 读取 "2 znaki"，而 `@MinLength(5)` 读取 "5 znaków"：

```json
{
  "isInt": "{path} musi być liczbą całkowitą",
  "isString": "{path} musi być tekstem",
  "min": "{path} musi wynosić co najmniej {constraint1}",
  "arrayNotEmpty": "{path} musi zawierać co najmniej jeden element",
  "minLength": {
    "one": "{path} musi mieć co najmniej {count} znak",
    "few": "{path} musi mieć co najmniej {count} znaki",
    "many": "{path} musi mieć co najmniej {count} znaków",
    "other": "{path} musi mieć co najmniej {count} znaku"
  },
  "matches": "{path} ma nieprawidłowy format"
}

```

没有翻译的约束会保留 `class-validator` 消息，因此您可以一次翻译一个使用的约束。

对于嵌套对象，Nest 的 `ValidationPipe` 会将父路径放在每个消息的前面。`I18nValidationPipe` 保持翻译后的消息不变，因此每个消息自行决定：`path` 给出 `items.1.quantity`，而 `property` 只给出 `quantity`。没有翻译的消息会保留前缀。

客户在订单上设置了收货地址。其 ⟦DTO⟧ 依赖于目录中的 `minLength` 和 `matches` 条目，并为国家指定了一个特定于存储的消息：

```typescript title="orders/dto/shipping-address.dto.ts"
import { i18nValidationMessage } from '@nestjs/i18n';
import { IsIn, Matches, MinLength } from 'class-validator';

export class ShippingAddressDto {
  @MinLength(2)
  recipient: string;

  @MinLength(2)
  city: string;

  @Matches(/^[0-9-]{5,6}$/)
  postalCode: string;

  @IsIn(['US', 'PL', 'DE'], { message: i18nValidationMessage('orders.unsupportedCountry') })
  country: 'US' | 'PL' | 'DE';
}

```

```typescript title="orders/orders.controller.ts"
@Put(':id/shipping-address')
updateShippingAddress(
  @Param('id', orderIdPipe) id: number,
  @Body() address: ShippingAddressDto,
) {
  return this.ordersService.updateShippingAddress(id, address);
}

```

一位发送单字母收件人、四位邮政编码和 `AT` 作为国家的德国客户会收到三个翻译后的消息。[Try it](#try-it) 部分显示了响应。

##### 使用 Zod

如果您的应用程序使用 Zod、Valibot、ArkType 或其他 [Standard Schema](https://standardschema.dev/) 库进行验证，请绑定 `I18nStandardSchemaValidationPipe` 而不是 `I18nValidationPipe`。它是 Nest [`StandardSchemaValidationPipe`](/techniques/validation#基于模式的验证) 的即插即用替代品，应用程序绑定其中一个管道，而不是两个：

```typescript title="app.module.ts"
providers: [{ provide: APP_PIPE, useValue: new I18nStandardSchemaValidationPipe() }],

```

这里与 Zod 模式相同的输入。库消息是纯字符串，因此 `i18nIssueMessage()` 在消息本身中编码了一个翻译键，这适用于任何标准 ⟦Schema⟧ 库：

```typescript title="orders/orders.schemas.ts"
import { i18nIssueMessage } from '@nestjs/i18n';
import { z } from 'zod';

export const orderItemSchema = z.object({
  productId: z.string(),
  quantity: z.number().int().min(1).max(10, i18nIssueMessage('orders.tooManyItems')),
});

export const createOrderSchema = z.object({
  items: z.array(orderItemSchema).nonempty(),
});
export type CreateOrderDto = z.infer<typeof createOrderSchema>;

export const shippingAddressSchema = z.object({
  recipient: z.string().min(2),
  city: z.string().min(2),
  postalCode: z.string().regex(/^[0-9-]{5,6}$/),
  country: z.enum(['US', 'PL', 'DE'], i18nIssueMessage('orders.unsupportedCountry')),
});
export type ShippingAddress = z.infer<typeof shippingAddressSchema>;

```

主体参数声明其 ⟦Schema⟧ 而不是一个类：

```typescript title="orders/orders.controller.ts"
import {
  createOrderSchema,
  shippingAddressSchema,
  type CreateOrderDto,
  type ShippingAddress,
} from './orders.schemas.js';
// ...
@Post()
create(@Body({ schema: createOrderSchema }) dto: CreateOrderDto) {
  // ...
}

@Put(':id/shipping-address')
updateShippingAddress(
  @Param('id', orderIdPipe) id: number,
  @Body({ schema: shippingAddressSchema }) address: ShippingAddress,
) {
  return this.ordersService.updateShippingAddress(id, address);
}

```

没有明确键的 issue 会由库分配的代码从最具体的键到最不具体的键进行查找：

- **先格式。** 失败的 regex 读取 `validation.invalid_format.regex`。
- **然后是来源。** Zod 对短字符串、小数字和短数组都报告 `too_small`，并说明在 `origin` 中。短字符串读取 `validation.too_small.string`，因此目录可以谈论字符而不会将数字弄错。
- **最后是代码本身**，例如 `validation.too_small`。

Valibot 的 issue `type` 也是如此工作。消息可以使用上述 `property` 和 `path` 占位符，使用库自身的文本 `message`，以及 issue 的参数，例如 `minimum` 或 `expected`。`count` 包含数字 `minimum` 或 `maximum`，因此 "2 znaki" 和 "5 znaków" 都能正确显示，`orders.tooManyItems` 针对 `.max(10)` 也是如此。这里是波兰语目录，issue-code 条目在约束名称前：

#### 本地化 GraphQL 字段

此步骤适用于使用 `@nestjs/graphql` 提供 GraphQL 的应用程序。移动应用通过 Apollo 驱动和在 `AppModule` 中注册的 [code first](/graphql/quick-start#代码优先) 模式通过 GraphQL 读取订单：

```typescript title="app.module.ts"
GraphQLModule.forRoot<ApolloDriverConfig>({
  driver: ApolloDriver,
  autoSchemaFile: true,
}),

```

对象类型暴露原始订单数据：

```typescript title="orders/order.model.ts"
import { Field, Float, Int, ObjectType } from '@nestjs/graphql';

@ObjectType('Order')
export class OrderModel {
  @Field(() => Int)
  id: number;

  @Field()
  status: string;

  @Field(() => Float)
  total: number;
}

```

本地化字段由字段解析器计算，与 REST 控制器使用的 `I18nService` 相同：

```typescript title="orders/orders.resolver.ts"
import { Args, Int, Parent, Query, ResolveField, Resolver } from '@nestjs/graphql';
import { I18nService } from '@nestjs/i18n';
import type { Order } from './order.entity.js';
import { OrderModel } from './order.model.js';
import { OrdersService } from './orders.service.js';

@Resolver(() => OrderModel)
export class OrdersResolver {
  constructor(
    private readonly ordersService: OrdersService,
    private readonly i18nService: I18nService,
  ) {}

  @Query(() => OrderModel)
  order(@Args('id', { type: () => Int }) id: number) {
    return this.ordersService.findOne(id);
  }

  @ResolveField(() => String)
  statusLabel(@Parent() order: Order) {
    return this.i18nService.t(`orders.status.${order.status}`);
  }

  @ResolveField(() => String)
  items(@Parent() order: Order) {
    return this.ordersService.describeItems(order);
  }
}

```

`statusLabel` 键是从 `OrderStatus` 联合类型构建的模板字面量，因此编译器仍然会检查每个状态是否都有标签。

在 Express 上，Apollo 在 Nest 的中间件之后挂载，因此来自 [Add catalogs and register the module](/application/i18n#add-catalogs-and-register-the-module) 的本地化中间件包装了每个 GraphQL 操作。`?lang`、`x-lang` 和 `Accept-Language` 的工作方式与 REST 完全相同，在解析器、字段解析器和守卫中。由 `findOne()` 抛出的 `NotFoundException` 会在 `errors[0].message` 中以翻译后的形式到达客户端。

> 警告 **警告** 本地化中间件不包装订阅（通过 WebSocket 运行）或挂载在它外部的 GraphQL 驱动。这包括常见情况 [global prefix](/faq/global-prefix)：Nest 在前缀下挂载中间件，而 Apollo 保持在 `/graphql`，因此在使用时请在 `GraphQLModule` 上设置 `useGlobalPrefix: true`。在中间件不运行时，该包会回退到全局拦截器，该拦截器从 GraphQL 上下文中的请求读取本地化（对于订阅，是 WebSocket 握手），并在守卫之后运行。字段解析器（包括订阅事件的解析器）只有在设置了 `fieldResolverEnhancers: ['interceptors']` 时才受保护，守卫看不到本地化，响应不携带 `Content-Language`。

#### 格式化价格和日期

订单摘要显示状态、项目数量、总额和订单日期，以每位客户期望的方式格式化：

```typescript title="orders/orders.service.ts"
getSummary(id: number) {
  const order = this.findOne(id);
  return {
    id: order.id,
    status: this.i18nService.t(`orders.status.${order.status}`),
    items: this.describeItems(order),
    total: this.i18nService.formatNumber(order.total, { style: 'currency', currency: 'USD' }),
    placedAt: this.i18nService.formatDate(order.createdAt, {
      dateStyle: 'long',
      timeZone: 'UTC',
    }),
  };
}

```

`formatNumber()` 和 `formatDate()` 使用请求的本地化包装 `Intl.NumberFormat` 和 `Intl.DateTimeFormat`。它们接受常规的 `Intl` 选项，以及一个覆盖当前本地化的 `locale` 选项，如 `t()` 所示。对于订单 #1001：

| Locale | `total` | `placedAt` |
| --- | --- | --- |
| `en` | $97.95 | September 14, 2026 |
| `pl` | 97,95 USD | 14 września 2026 |
| `de` | 97,95 $ | 14. September 2026 |
| `de-AT` | $ 97,95 | 14. September 2026 |

`de-AT` 采用奥地利格式，因为模块注册在 `fallbacks` 中列出了它。其消息仍然来自德语目录。

本地化不决定的两件事：

- **货币。** 本地化控制金额的写法，而不是其价值。商店以美元收费，因此每位客户都看到 USD。从订单或商店获取货币，绝不要从本地化获取。
- **时区。** 没有 `timeZone`，日期将以服务器时区格式化，这可能会改变日期。如果存储了客户的时区，请传入该时区，或者像这里一样以 UTC 格式化。

#### 使用客户保存的语言

客户在注册时选择一种语言，客户记录将其保存在 `locale` 字段中，例如 [mail chapter](/application/mail#send-it-in-the-customers-language) 的 `customers` 表。在这里，`CustomersService` 将客户保留在内存中，因为 `OrdersService` 保留订单。对于已登录的客户，该选择应优先于 `Accept-Language`，后者仅是其浏览器的默认设置。[`@nestjs/authentication`](/security/authentication) 的守卫，类似于 Passport 守卫，将已登录用户放在 `request.user` 上。

解析器在本地化中间件中运行，在守卫之前，在没有人登录时。设置 `afterGuards` 的解析器在守卫之后运行，并接收调用的 `executionContext`：

```typescript title="customers/customer-locale.resolver.ts"
import { Injectable } from '@nestjs/common';
import { LocaleResolver, type LocaleResolverInput } from '@nestjs/i18n';
import { CustomersService } from './customers.service.js';

@Injectable()
export class CustomerLocaleResolver extends LocaleResolver {
  // After guards, the authentication guard has put the signed-in user on the request
  readonly afterGuards = true;

  constructor(private readonly customersService: CustomersService) {
    super();
  }

  resolve({ executionContext }: LocaleResolverInput) {
    const request = executionContext?.switchToHttp().getRequest<{ user?: { id: number } }>();
    const user = request?.user;
    return user ? this.customersService.findOne(user.id)?.locale : undefined;
  }
}

```

Nest 实例化一个解析器类，因此可以注入提供者。将其放入应有的 `resolvers` 排名，并导入提供其注入内容的模块：

```typescript title="app.module.ts"
I18nModule.forRoot({
  // ...
  resolvers: [
    new QueryLocaleResolver('lang'),
    new HeaderLocaleResolver('x-lang'),
    CustomerLocaleResolver,
    new AcceptLanguageLocaleResolver(),
  ],
  imports: [CustomersModule],
  // ...
}),

```

解析器的顺序仍然决定：

- **`?lang` 和 `x-lang` 获胜。** 这是为本次请求做出的选择，由语言切换链接或应用程序设置决定。当其中一个匹配时，客户解析器不会运行。
- **保存的语言胜过 `Accept-Language`。** Zofia 保存了波兰语，所以她在任何浏览器中都阅读波兰语。Lukas 保存了 `de-AT`，它像任何候选者一样匹配，所以他获得奥地利格式。
- **匿名客户和没有支持的保存语言的客户** 获得其下方解析器找到的内容，这里是从 `Accept-Language` 获取的。

守卫会看到解析器在守卫之前找到的本地化，错误守卫抛出的响应（例如 401）也会看到它。处理程序及其之后的所有内容都会看到客户的本地化。解析器每次请求运行一次，也对具有多个根字段的 GraphQL 操作运行一次。通过 GraphQL，请求在 `GqlExecutionContext.create(executionContext).getContext().req`。

> 信息 **提示** 对已登录客户的响应现在取决于谁提问。此类响应通常是私有的，但如果共享缓存存储它们，请在解析器的 `varyHeaders` 中列出识别客户的头部，例如 `Authorization`，中间件会将其添加到 `Vary`。

当客户更改语言时，立即用新语言回复他们。`I18nContext.setLocale()` 会更改整个请求的本地化，包括 `Content-Language`：

```typescript title="customers/customers.controller.ts"
@Controller('customers')
export class CustomersController {
  constructor(
    private readonly customersService: CustomersService,
    private readonly i18nContext: I18nContext,
    private readonly i18nService: I18nService,
  ) {}

  @Put('me/locale')
  updateLocale(@Req() request: { user: { id: number } }, @Body('locale') locale: string) {
    const supported = this.i18nContext.setLocale(locale);
    if (!supported) {
      throw new BadRequestException(this.i18nService.t('customers.unsupportedLocale'));
    }

    this.customersService.updateLocale(request.user.id, supported);
    return { locale: supported, message: this.i18nService.t('customers.localeUpdated') };
  }
}

```

`setLocale()` 以与解析相同的方式匹配本地化并返回匹配项：`de-DE` 变为 `de`。对于商店不写入的语言，它返回 `undefined` 并保持本地化不变，因此错误是客户正在阅读的语言中的错误。这两个消息存在于每种语言中的新 `customers` 目录中，在 `Translations` 中使用 `customers: typeof customers` 注册：

```json
{
  "localeUpdated": "Erledigt! Ab jetzt schreiben wir Ihnen auf Deutsch.",
  "unsupportedLocale": "Wir schreiben nur auf Englisch, Polnisch und Deutsch."
}

```

#### 微服务和 WebSocket 网关

消息处理器和 WebSocket 网关不会经过 HTTP 中间件。在那里，模块在一个全局拦截器中解析区域设置，使用相同的解析器，因此服务、异常和 `t()` 函数的行为与 HTTP 请求相同。

消息没有头部或查询字符串，但解析器会接收到 `executionContext`，因此解析器可以读取生产者放入消息本身中的区域设置。将其添加到微服务 `I18nModule` 的 `resolvers` 中：

```typescript title="common/message-locale.resolver.ts"
import { LocaleResolver, type LocaleResolverInput } from '@nestjs/i18n';

export class MessageLocaleResolver extends LocaleResolver {
  resolve({ executionContext }: LocaleResolverInput) {
    if (executionContext?.getType() !== 'rpc') {
      return undefined;
    }
    return executionContext.switchToRpc().getData<{ locale?: string }>()?.locale;
  }
}

```

解析器也可以以相同的方式读取消息的传输元数据，例如 NATS 或 Kafka 消息的头部，来自 `executionContext.switchToRpc().getContext()`。

对于网关，内置解析器会读取连接升级请求的头部和查询字符串。Socket.IO 将该请求保留为握手，解析器在那里找到它。`ws` 库在 `@nestjs/platform-ws` 的 `WsAdapter` 背后不保留任何内容，因此在客户端连接时将请求存储在 `client.request` 上（`@nestjs/authentication` 的 `WsAuthenticator` 执行相同操作）：

```typescript title="orders/order-updates.gateway.ts"
@WebSocketGateway({ path: '/orders/updates' })
export class OrderUpdatesGateway implements OnGatewayConnection {
  constructor(private readonly ordersService: OrdersService) {}

  handleConnection(client: WebSocket & { request?: IncomingMessage }, request: IncomingMessage) {
    // The ws library keeps no reference to the upgrade request, whose headers and query the resolvers read
    client.request = request;
  }

  @SubscribeMessage('orders.summary')
  summary(@MessageBody() id: number) {
    return { event: 'orders.summary', data: this.ordersService.getSummary(id) };
  }
}

```

连接到 `/orders/updates?lang=de` 的客户端读取德语摘要。拦截器在守卫之后运行，因此在这些路径上，守卫看到的是默认区域设置，守卫抛出的错误是默认区域设置中的错误。管道和处理器看到解析后的区域设置，而带有 `afterGuards` 的解析器无需额外操作：这里的每个解析器都已经在守卫之后运行了。

#### 处理缺失的键和重新加载目录

缺失的翻译在开发和 CI 中应中断构建，在生产环境中应静默降级。这是最终的 `AppModule`：

```typescript title="app.module.ts"
import { ApolloDriver, type ApolloDriverConfig } from '@nestjs/apollo';
import { Module } from '@nestjs/common';
import { APP_PIPE } from '@nestjs/core';
import { GraphQLModule } from '@nestjs/graphql';
import {
  AcceptLanguageLocaleResolver,
  HeaderLocaleResolver,
  I18nModule,
  I18nValidationPipe,
  JsonI18nLoader,
  QueryLocaleResolver,
} from '@nestjs/i18n';
import { join } from 'node:path';
import { CustomerLocaleResolver } from './customers/customer-locale.resolver.js';
import { CustomersModule } from './customers/customers.module.js';
import { OrdersModule } from './orders/orders.module.js';

const env = process.env.NODE_ENV ?? 'development';

@Module({
  imports: [
    I18nModule.forRoot({
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
        watch: env === 'development',
      }),
      resolvers: [
        new QueryLocaleResolver('lang'),
        new HeaderLocaleResolver('x-lang'),
        CustomerLocaleResolver,
        new AcceptLanguageLocaleResolver(),
      ],
      imports: [CustomersModule],
      missingKey: env === 'production' ? 'fallback' : 'throw',
    }),
    GraphQLModule.forRoot<ApolloDriverConfig>({
      driver: ApolloDriver,
      autoSchemaFile: true,
    }),
    CustomersModule,
    OrdersModule,
  ],
  providers: [
    {
      provide: APP_PIPE,
      useValue: new I18nValidationPipe({ whitelist: true, transform: true }),
    },
  ],
})
export class AppModule {}

```

`missingKey` 选项决定了当请求的区域设置找不到键时会发生什么：

- **在生产环境外部 `'throw'`。** `t()` 和 `translate()` 抛出 `I18nMissingKeyError`，请求以 500 失败。一个仅存在于英语中的波兰语消息也会失败，因为此策略从不回退到默认区域设置。Vitest 将 `NODE_ENV` 设置为 `test`，因此您的测试套件使用此策略运行。
- **在生产环境内 `'fallback'`。** 缺失的波兰语消息将从默认区域设置（英语）中获取，警告会指明键和区域设置，每个对只警告一次。不存在的键将返回键本身并记录警告，每个键只警告一次。

`de-AT` 到 `de` 的回退和区域到基础的匹配适用于每种策略。通过约束名称或问题代码查找的验证消息绝不会抛出：没有翻译的约束或问题将保留库的消息。您使用 `i18nValidationMessage()` 或 `i18nIssueMessage()` 命名的键遵循策略，例如 `t()`。其他策略是 `'key'`、`'empty'` 以及接收键和区域设置的函数。

> info **提示** 回退是按键进行的。当消息按 [Translate order confirmations](/application/i18n#translate-order-confirmations) 组合时，波兰语客户可能会收到一个包含波兰语复数的英语句子。警告会告知您发生了什么；[Testing](/application/i18n#测试) 中的目录测试会阻止其发布。

使用 `watch: true`，JSON 加载器会监视目录并当文件更改时重新加载它，因此翻译人员可以在不重启应用程序的情况下编辑消息。仅在开发环境中启用它：

- **重新加载是原子的。** 整个目录在一个步骤中重新读取并替换，因此请求永远不会看到新旧消息的混合。
- **损坏的文件被忽略。** 如果文件解析失败，则继续使用上一个目录，并且错误会记录文件路径。下一个有效的保存将被拾取。
- **关闭时停止监视。** 当应用程序关闭时，监视器关闭。在 `main.ts` 中调用 `app.enableShutdownHooks()` 也可以在终止信号时关闭它。

在 `nest-cli.json` 中启用 `watchAssets` 后，CLI 会将编辑后的目录复制到 `dist`，加载器从中读取。

##### 来自配置的选项

教程直接读取 `process.env` 以保持简洁。在应用程序中，通过 [`@nestjs/config`](/application/configuration) 使用验证模式加载环境，并使用 `forRootAsync()` 注册模块。其工厂接收注入的 `ConfigService` 并返回选项：

```typescript title="app.module.ts"
I18nModule.forRootAsync({
  inject: [ConfigService],
  useFactory: (configService: ConfigService) => {
    const env = configService.get<string>('NODE_ENV', 'development');
    return {
      defaultLocale: 'en',
      supportedLocales: ['en', 'pl', 'de'],
      fallbacks: { 'de-AT': 'de' },
      loader: new JsonI18nLoader({
        path: join(import.meta.dirname, 'i18n'),
        watch: env === 'development',
      }),
      missingKey: env === 'production' ? 'fallback' : 'throw',
    };
  },
  // The list has a class, which Nest instantiates, so it stays next to useFactory
  resolvers: [
    new QueryLocaleResolver('lang'),
    new HeaderLocaleResolver('x-lang'),
    CustomerLocaleResolver,
    new AcceptLanguageLocaleResolver(),
  ],
  imports: [CustomersModule],
}),

```

工厂可以返回加载器、解析器和格式化器实例，但不能返回类：Nest 在构建模块之前实例化类，在任何工厂运行之前。因此，包含 `CustomerLocaleResolver` 的 `resolvers` 保持在顶层，使用 `imports`。返回类的工厂或两个位置设置的选项集会在启动时因命名选项的消息而失败。

为了将选项保留在一个单独的类中，请将其作为 `useClass` 传递。它实现了 `I18nOptionsFactory`，Nest 调用其 `createI18nOptions()` 方法：

```typescript title="i18n/i18n-config.service.ts"
@Injectable()
export class I18nConfigService implements I18nOptionsFactory {
  constructor(private readonly configService: ConfigService) {}

  createI18nOptions(): I18nModuleOptions {
    const env = this.configService.get<string>('NODE_ENV', 'development');
    return {
      defaultLocale: 'en',
      // ...
    };
  }
}

```

```typescript title="app.module.ts"
I18nModule.forRootAsync({
  useClass: I18nConfigService,
  resolvers: [
    // ...
  ],
  imports: [CustomersModule],
}),

```

模块最终拥有的选项可以通过 `I18N_MODULE_OPTIONS` 令牌注入到您自己的依赖于它们的提供者中。

##### 自定义加载器

翻译人员通常在翻译平台中工作，该平台将每个目录导出为一个 JSON 文档。加载器扩展 `I18nLoader`：`load()` 以区域设置为键返回目录，可选的 `watch()` 将新目录传递给回调，用于热重载。此加载器在启动时以及每五分钟再次获取导出：

```typescript title="i18n/remote-i18n.loader.ts"
import { Logger } from '@nestjs/common';
import { I18nLoader, type I18nCatalogs } from '@nestjs/i18n';

/** Catalogs a translation platform exports as one JSON document, fetched again every `interval` ms. */
export class RemoteI18nLoader extends I18nLoader {
  private readonly logger = new Logger(RemoteI18nLoader.name);

  constructor(
    private readonly url: string,
    private readonly interval = 5 * 60_000,
  ) {
    super();
  }

  async load(): Promise<I18nCatalogs> {
    const response = await fetch(this.url, { signal: AbortSignal.timeout(10_000) });
    if (!response.ok) {
      throw new Error(`GET ${this.url} answered ${response.status}`);
    }
    return (await response.json()) as I18nCatalogs;
  }

  watch(onChange: (catalogs: I18nCatalogs) => void): () => void {
    const timer = setInterval(() => {
      this.load().then(onChange, (err: Error) =>
        this.logger.warn(`Keeping the current catalogs: ${err.message}`),
      );
    }, this.interval);
    // Polling alone doesn't keep the process alive
    timer.unref();
    return () => clearInterval(timer);
  }
}

```

将实例作为 `loader` 传递。启动时的获取失败会导致引导失败，而轮询失败会保持目录的使用。模块在初始化时调用 `watch()`，当它关闭时函数 `watch()` 返回。新目录像第一个目录一样被检查，不匹配的集合（例如没有默认区域设置目录的集合）会被记录并忽略。要从数据库读取目录，请传递一个加载器类，Nest 会使用注入的仓储实例化它，并将仓储的模块列在 `imports` 中。

#### 使用 ICU 消息语法

内置语法具有占位符和作为目录对象的复数形式。Crowdin 和 Lokalise 等翻译平台通常以 ICU MessageFormat 导出目录，该格式也具有精确匹配，例如 `=0`、`select`（对于依赖于值的消息，例如宠物的物种）和 `selectordinal`（第 1、第 2、第 3）。以下是 ICU 中的波兰语 `items` 消息：

```json
{
  "items": "{count, plural, one {# produkt} few {# produkty} many {# produktów} other {# produktu}}"
}

```

`formatter` 选项插入了另一种语法。一个格式化器扩展 `I18nMessageFormatter` 并实现 `format()`，后者接收消息、参数和区域设置。此格式化器将消息传递给您的应用程序安装的 [`intl-messageformat`](https://formatjs.github.io/docs/intl-messageformat/) 库：

```typescript title="i18n/icu-message.formatter.ts"
import { I18nMessageFormatter } from '@nestjs/i18n';
import { IntlMessageFormat } from 'intl-messageformat';

export class IcuMessageFormatter extends I18nMessageFormatter {
  // Parsing a message costs far more than formatting it, and the catalogs hold a fixed set
  private readonly compiled = new Map<string, IntlMessageFormat>();

  format(message: string, args: Record<string, unknown>, locale: string): string {
    const key = `${locale}\u0000${message}`;
    let compiled = this.compiled.get(key);
    if (!compiled) {
      compiled = new IntlMessageFormat(message, locale, undefined, { ignoreTag: true });
      this.compiled.set(key, compiled);
    }
    return String(compiled.format<unknown>(args));
  }
}

```

`ignoreTag` 将 `<` 和 `>` 保留为文本，否则库会读取富文本标签。将实例或 Nest 实例化的类作为 `formatter` 传递：

```typescript title="app.module.ts"
I18nModule.forRoot({
  // ...
  formatter: new IcuMessageFormatter(),
}),

```

设置了格式化器后：

- **教程的目录保持不变。** 占位符是一个简单的 ICU 参数，复数对象仍然有效：模块选择形式，格式化器进行格式化。波兰语 `items` 将 "5 produktów" 读取为复数对象，也如上述 ICU 消息所示。
- **区域设置是请求的。** 从德语目录读取的消息将为 `de-AT` 格式化，因此带有货币样式的数字参数读取 `$ 97,95`。回退到默认区域设置的消息将为默认区域设置格式化，其语法是该区域设置的语法。
- **键保持检查，复数计数不保持。** 编译器要求复数对象有一个数字 `count`，但 ICU 复数对它来说是一个字符串，因此请自行传递其参数。

`'throw'` 策略会捕获测试执行的路径上的缺失键。目录测试会捕获其余部分：每个区域设置都必须具有与英语相同的键和占位符，并且每个复数消息都必须具有其语言所需的形式。`Intl.PluralRules` 知道这些形式是什么：

```typescript title="test/catalogs.spec.ts"
import { JsonI18nLoader, type I18nCatalog } from '@nestjs/i18n';
import { join } from 'node:path';

type Message = string | Record<string, string>;

/** Flattens a catalog to [key, message] pairs; plural forms count as one message. */
function messages(tree: I18nCatalog, prefix = ''): [string, Message][] {
  return Object.entries(tree).flatMap(([name, value]): [string, Message][] =>
    typeof value === 'string' || 'other' in value
      ? [[prefix + name, value as Message]]
      : messages(value, `${prefix}${name}.`),
  );
}

const placeholders = (message: Message) =>
  [...new Set(JSON.stringify(message).match(/\{\w+\}/g))].sort();

const loader = new JsonI18nLoader({ path: join(import.meta.dirname, '../src/i18n') });
const catalogs = await loader.load();
const english = new Map(messages(catalogs.en));

describe.each(Object.keys(catalogs))('the %s catalog', (lang) => {
  const translated = new Map(messages(catalogs[lang]));

  it('has the same keys and placeholders as the English one', () => {
    expect([...translated.keys()].sort()).toEqual([...english.keys()].sort());
    for (const [key, message] of translated) {
      expect(placeholders(message), key).toEqual(placeholders(english.get(key)!));
    }
  });

  it('has every plural form the language needs', () => {
    const forms = new Intl.PluralRules(lang).resolvedOptions().pluralCategories;
    for (const [key, message] of translated) {
      if (typeof message === 'object') {
        expect(Object.keys(message), key).toEqual(expect.arrayContaining(forms));
      }
    }
  });
});

```

从波兰语 `items` 消息中删除 `many` 形式，第二个测试将以波兰语所需的形式列表失败。

#### 生产检查清单

- **发布目录。** 检查 `nest build` 之后是否存在 `dist/i18n`。加载器在启动时读取目录，缺少目录会导致引导失败。
- **在生产中使用 `'fallback'`，在其他地方使用 `'throw'`**，并在 CI 中运行目录测试。监控生产日志以查找回退警告。
- **在生产中关闭 `watch`。** 热重载是开发工具。
- **固定 `supportedLocales`。** 否则 `i18n` 下的每个目录都成为一个区域设置，包括在应用运行时启用 `watch` 时出现的目录。
- **向 `fallbacks` 添加格式化区域。** 区域解析到其基础语言，除非它被列出，然后它也像基础语言一样格式化。
- **在请求外部设置区域设置。** 定时任务、队列消费者和传出电子邮件没有请求，因此 `I18nService` 在那里回退到默认区域设置，并且 `t()` 函数返回键。保存每个客户的首选区域设置，并在 `I18nContext.run()` 内部运行工作。
- **注意缓存。** 对相同 URL 的响应因 `Accept-Language` 和 `x-lang` 而不同。中间件在 `Vary` 中列出两者；请检查您的缓存或 CDN 是否遵守此设置。`lang` 查询参数是 URL 的一部分，因此不需要额外操作。
- **将 GraphQL 保持在全局前缀下。** 使用 `setGlobalPrefix()`，区域设置中间件仅覆盖前缀下的路由。为 `GraphQLModule` `useGlobalPrefix: true`，或在解析器上设置守卫，否则将看不到区域设置（参见 [Localize GraphQL fields](/application/i18n#localize-graphql-fields)）。
- **转义最终出现在 HTML 中的消息。** 例如客户名称等参数是按原样插入的。这对于 JSON 响应是正确的，但 HTML 电子邮件必须像任何其他文本一样转义消息。
- **将数字和日期留给区域设置处理，将货币和时区排除在外。** 参见 [Format prices and dates](/application/i18n#format-prices-and-dates)。

#### 参考

##### 模块选项

`I18nModule.forRoot()` 接受这些选项。`forRootAsync()` 从其工厂（`useFactory` 带有 `inject`，或实现 `I18nOptionsFactory` 的 `useClass` 或 `useExisting` 类）获取相同的值，而 `imports`、`isGlobal` 和加载器、解析器或格式化器类保持在顶层。参见 [Options from configuration](/application/i18n#options-from-configuration)。解析后的选项可通过 `I18N_MODULE_OPTIONS` 令牌注入。

| 选项 | 默认值 | 描述 |
| --- | --- | --- |
| `loader` | required | 目录的来源：如 `I18nLoader` 实例（例如 `JsonI18nLoader`），或 Nest 实例化的加载器类。参见 [Add catalogs and register the module](/application/i18n#add-catalogs-and-register-the-module)。 |
| `resolvers` | `[new AcceptLanguageLocaleResolver()]` | 区域设置解析器，按顺序尝试：实例或 Nest 实例化的类。 |
| `formatter` | 内置语法 | 一个将消息转换为文本的 `I18nMessageFormatter` 实例或 Nest 实例化的类。参见 [Use ICU message syntax](/application/i18n#use-icu-message-syntax)。 |
| `defaultLocale` | `'en'` | 当没有解析器找到受支持的区域设置且在请求外部时使用。 |
| `supportedLocales` | 已加载的区域设置 | 请求可以获得的区域设置，作为 BCP 47 标签。 |
| `fallbacks` | none | 一个将区域设置映射到其消息来源的对象的对象，例如 `'de-AT': 'de'`。键被视为受支持的区域设置。 |
| `missingKey` | `'fallback'` | 缺失键返回的内容：`'fallback'`、`'key'`、`'empty'`、`'throw'` 或接收键和区域设置的函数。参见 [Handle missing keys and reload catalogs](/application/i18n#handle-missing-keys-and-reload-catalogs)。 |
| `logMissingKeys` | `'once'` | 针对每个键发出关于缺失键和默认区域设置回退的警告 `'once'`、`'always'` 或 `'never'`。 |
| `responseHeaders` | `true` | 在 HTTP 响应上设置 `Content-Language` 和 `Vary`。 |
| `imports` | none | 导出提供者加载器、解析器和格式化器类的模块会注入它们。 |
| `isGlobal` | `true` | 全局注册模块。 |

`JsonI18nLoader` 接受 `path`（每个区域设置一个子目录的目录）和 `watch`（默认为 `false`），后者在文件更改时重新加载目录。`InMemoryI18nLoader` 将目录作为按区域设置键组织的对象接收。

##### 区域设置解析器

| 解析器 | 读取 | 默认名称 |
| --- | --- | --- |
| `QueryLocaleResolver` | 查询参数 | `lang` |
| `HeaderLocaleResolver` | 请求头 | `x-lang` |
| `AcceptLanguageLocaleResolver` | `Accept-Language`，按 `q` 值排序 | 无 |
| `CookieLocaleResolver` | `Cookie` 头中的 Cookie | `lang` |

自定义解析器继承自 `LocaleResolver` 并实现 `resolve()`，它接收请求 `headers` 和 `query`，并返回一个候选值、候选值列表或无值。它在 `varyHeaders` 中列出了它读取的头。设置了 `afterGuards` 后，它在守卫之后运行，保持其排名，并接收 `executionContext`，就像微服务、WebSocket 网关和 GraphQL 订阅中的每个解析器一样。参见 [Use the customer's saved language](/application/i18n#use-the-customers-saved-language)。

##### 翻译 API

- `I18nService.t(key, options)`：为当前区域设置进行翻译。`options` 接收 `args`、占位符值（一个数字 `count` 用于选择复数形式）和 `locale`，一个明确的区域设置。参见 [Translate order confirmations](/application/i18n#translate-order-confirmations)。`I18nService<OtherTranslations>` 将键与另一个目录形状进行检查。
- `I18nService.translate(key, options)`：与未检查的键相同，用于运行时构建的键。
- `I18nService.exists(key, locale)`：检查一个键是否有消息。
- `I18nService.formatNumber(value, options)` 和 `formatDate(value, options)`：在当前区域设置中进行 `Intl` 格式化，带有常规的 `Intl` 选项以及 `locale`。参见 [Format prices and dates](/application/i18n#format-prices-and-dates)。
- `I18nService.matchLocale(candidate)`：将一个区域设置（例如保存在个人资料上的区域设置）映射到受支持的区域设置，或 `undefined`。
- `I18nService.defaultLocale` 和 `supportedLocales`：配置的区域设置，用于语言选择器。
- `I18nContext.locale` 和 `I18nContext.run(locale, fn)`：读取当前区域设置，或为请求外部代码设置当前区域设置。
- `I18nContext.setLocale(locale)`：更改请求的其余部分的区域设置并返回匹配的区域设置，或对于不受支持的区域设置返回 `undefined`（不改变任何内容）。它在请求外部抛出，在守卫中（在区域设置解析之前运行）的微服务、WebSocket 网关和 GraphQL 订阅中也抛出。
- `@CurrentLocale()`：作为处理程序参数的当前区域设置。
- `t(key, options)`：对于没有依赖注入的代码，使用 `I18nService.t()`。在请求外部，它返回键。参见 [Localize exceptions](/application/i18n#localize-exceptions)。
